# Python React starter

A three-container web app: a React frontend, a FastAPI backend and a Postgres
database. It ships with one example feature (a list of messages) that shows a request
going from React to FastAPI to Postgres and back. Replace it with your own.

There are matching TypeScript (Hono) and Java (Spring Boot) starters with the same
API, the same frontend and the same `mise` tasks.

| Part     | Stack                                                                          |
| -------- | ------------------------------------------------------------------------------ |
| Frontend | React, Vite, a client generated from the API contract by `@hey-api/openapi-ts` |
| Backend  | FastAPI, pydantic, SQLAlchemy (async), httpx, logging with rich                |
| Database | Postgres 18, migrations generated by Alembic and applied by dbmate             |
| Tooling  | mise, uv, ruff, mypy, oxlint, oxfmt, strict TypeScript, Docker Compose         |

## Layout

```
mise.toml               Tool versions and every task you will run
compose.yaml            The deployed stack: web, backend, db. Coolify reads this file.
compose.override.yaml   Local additions: published ports, a required .env
.env.example            Local settings. Copy it to .env.
backend/
  src/app/main.py       Creates the app. `python -m app.main` runs it.
  src/app/config/       Settings, database session and logging
  src/app/routes/       HTTP handlers, one file per resource
  src/app/schemas/      pydantic request and response models
  src/app/models/       SQLAlchemy tables. The source of truth for the schema.
  src/app/middleware/   Request logging
  migrations/           Generated SQL migrations. Commit these.
  openapi.json          The API contract, generated from the routes. Commit it.
  scripts/              Writes openapi.json and generates migrations
frontend/
  src/App.tsx           The page
  src/api/generated/    Client generated from the contract (not committed)
  nginx.conf            Deployed web server: serves the app and proxies /api
.agents/rules/          Extra rules for AI agents, per folder
AGENTS.md               Rules for agents and humans
```

## Getting started

You need [mise](https://mise.jdx.dev) and Docker.

```sh
mise install
cp .env.example .env
mise run setup:dev
mise run dev
```

Open <http://localhost:5173> and press the button. The API runs on
<http://localhost:3000/api/v1>, with docs at <http://localhost:3000/api/v1/docs>.

`mise tasks` lists every task. The ones you will use most:

| Task                                      | What it does                                                    |
| ----------------------------------------- | --------------------------------------------------------------- |
| `mise run dev`                            | Start the db, then run the backend and frontend with hot reload |
| `mise run contract`                       | Regenerate `backend/openapi.json` and the frontend client       |
| `mise run db:dev:migrate:generate <name>` | Write a SQL migration from your changes to the models           |
| `mise run db:dev:migrate:up`              | Apply pending migrations                                        |
| `mise run db:dev:migrate:status`          | Show whether the database is missing migrations                 |
| `mise run db:dev:migrate:down`            | Roll back the latest migration                                  |
| `mise run db:dev:studio`                  | Open Prisma Studio on the dev database (:5555)                  |
| `mise run db:dev:psql`                    | Open psql in the database                                       |
| `mise run check`                          | Run what CI runs: format check, lint, typecheck, contract check |
| `mise run fmt:fix`                        | Format everything                                               |
| `mise run stack:dev:up`                   | Build and run all three containers, as deployed, on :8080       |

## The API contract

The routes and pydantic schemas are the source of truth. `mise run contract` does two
things:

1. `contract:generate` writes `backend/openapi.json` from the app. FastAPI builds the
   spec itself; `scripts/openapi.py` only saves it. Commit this file.
2. `contract:client` generates a typed client with zod validators in
   `frontend/src/api/generated/`. This folder is gitignored.

`mise run check` fails if `backend/openapi.json` is out of date with the routes.

To add a route, copy `backend/src/app/routes/messages.py`, add its router in
`routes/__init__.py` and run `mise run contract`. The frontend then has a new function
named after the handler, in camelCase.

## The database

The models in `backend/src/app/models/` describe every table. Migrations are plain SQL
files in `backend/migrations/`, with an up and a down section.

1. Edit a model, or add one and import it in `models/__init__.py`.
2. Run `mise run db:dev:migrate:generate describe_your_change`. Alembic compares the
   models with your database, and `scripts/generate_migration.py` writes the SQL for
   the difference to a new file. Nothing is written if nothing changed.
3. Read the SQL, then run `mise run db:dev:migrate:up`.
4. Commit the model and the migration together.

[dbmate](https://github.com/amacneil/dbmate) applies the files. Each one has a
`-- migrate:up` section and a `-- migrate:down` section, and
`mise run db:dev:migrate:down` runs the down section of the latest one.

After pulling a teammate's migration, `mise run db:dev:migrate:status` tells you
whether your database is behind, and `mise run db:dev:migrate:up` catches it up. The
backend container applies pending migrations every time it starts, so deployed
environments stay in sync on their own.

Queries are SQL too. Use `select()`, `insert()`, `update()`, `delete()` or `text()`,
as `routes/messages.py` does, not `session.query()` or `session.add()`.

`mise run db:dev:studio` opens Prisma Studio on <http://localhost:5555>, already
connected to the dev database, to browse and edit rows. For raw SQL, use
`mise run db:dev:psql`.

`mise run db:dev:reset` wipes the local database and reapplies everything.

## Logging

Logs use the standard `logging` module. In development (`mise run dev`) they go
through rich, with colors and readable tracebacks. When deployed they are plain lines
on stdout. Get a logger with `logging.getLogger(__name__)`.

## Environment variables

`.env` holds your local values and is never committed. `.env.example` lists every
variable with values that work locally. mise loads `.env` for every task, and Docker
Compose reads it too. If port 5432 is taken, change `POSTGRES_PORT` and the port in
`DATABASE_URL`.

To add a variable, add it to `.env.example`, to `Settings` in
`backend/src/app/config/settings.py`, and to the `backend` service in `compose.yaml`.
Secrets belong in the backend only: anything the frontend uses ends up in the browser.

## Deploying on Coolify

1. Create a resource from this repo with the **Docker Compose** build pack, base
   directory `/` and compose file `/compose.yaml`.
2. Give the `web` service a domain that includes its port, for example
   `https://myapp.example.com:8080`. Do not give `backend` or `db` a domain.
3. Deploy. Coolify generates `SERVICE_USER_POSTGRES` and `SERVICE_PASSWORD_POSTGRES`
   once and keeps them for that environment.

## Removing the example

1. Delete `routes/messages.py` and its line in `routes/__init__.py`, and
   `schemas/message.py`.
2. Delete `models/message.py` and its import in `models/__init__.py`, run
   `mise run db:dev:migrate:generate remove_messages`, then
   `mise run db:dev:migrate:up`.
3. Replace `frontend/src/App.tsx`, then run `mise run contract`.
